Step 01

Plan the Complete Website & Generate the Master Prompt

Start with Requirements, Pages, Folder Structure, and Database Planning

The most critical phase of AI-assisted engineering is deep contextual requirement scoping. Never prompt for code until the database entity models, role matrices, and file boundaries are explicitly mapped.

Actionable Step Tasks:
  1. Describe the business model, operational domain, and target personas.
  2. Draft the public website page hierarchy (Home, About, Services, Contact, etc.).
  3. Enumerate every administrative view (Dashboard, User Mgmt, Settings, Audit Logs).
  4. Define user roles and explicit permission boundaries (Super Admin, Editor, Customer).
  5. Document every CRUD operation and validation rule for incoming form requests.
  6. Standardize the clean PHP folder structure and separation of concerns.
  7. Draft normalized MySQL schema relationships, primary keys, and foreign indices.
  8. Establish email transaction points using PHPMailer and SMTP credentials.
  9. Define security policies (CSRF, PDO prepared statements, input sanitization).
  10. Ask ChatGPT to synthesize a cohesive, comprehensive Master Architecture Prompt.

Step 02

Generate Website UI & PHP Files with Gemini Flash

Use One Master Prompt and Generate the Project Step by Step

Execute a disciplined, incremental code generation loop using Gemini Flash. Never prompt for the entire application at once. Build modularly: UI first, then schemas, database singletons, and CRUD controllers.

Gemini Flash Generation Rules:
  • Never generate the entire repository in one prompt: Divide tasks by individual files.
  • Specify exact relative file paths: Ensure the AI explicitly prefixes every file with its folder path.
  • Demand 100% complete files: Prohibit comments like /* Code remains unchanged here */.
  • Lock frontend design first: Approve HTML/CSS prototypes prior to wrapping them in PHP dynamic loops.
  • Track an ongoing dependency checklist: Ensure variable names and database table columns match across all files.
Expected Result: Production-ready, validated PHP files, modular partials (header/footer), and complete schema.sql ready for local execution.
Common Mistakes to Avoid: Blindly pasting code without reviewing database connection names; letting AI overwrite existing working files without version control.
Step 03

Install XAMPP & Run the Website Locally

Set Up Apache, MySQL, and Localhost

Establish an isolated local development environment using XAMPP so your PHP scripts execute through Apache and query a local MySQL database.

Execution Workflow:
  1. Download and install XAMPP from the official Apache Friends website.
  2. Launch XAMPP Control Panel and boot Apache and MySQL.
  3. Navigate to the document root: C:\xampp\htdocs\ (or /Applications/XAMPP/htdocs/ on macOS).
  4. Create your project sub-folder: my-php-project.
  5. Place all your generated PHP files and assets into this directory.
  6. Open http://localhost/phpmyadmin/ in your browser.
  7. Create a new database (e.g., portal_db) using utf8mb4_unicode_ci collation.
  8. Click Import and upload your database/schema.sql file.
  9. Update your config/database.php credentials (typically user: root, password: "").
  10. Access your running app in the browser at http://localhost/my-php-project/.
Expected Result: Apache & MySQL services active, database tables visible in phpMyAdmin, and the homepage rendering via localhost.
Common Mistakes to Avoid: Port 80 conflicts with Skype or IIS; leaving database connection passwords blank in production; forgetting to start the MySQL service.
Step 04

Open the Entire Project in VS Code

Import the Project and Organize All Files

VS Code serves as your command center for inspecting file trees, modifying templates, and diagnosing errors.

Workspace Best Practices:
  • Open the root folder (htdocs/my-php-project) directly to maintain relative path integrity.
  • Install indispensable extensions: PHP Intelephense, Prettier, and MySQL Workbench/Viewer.
  • Initialize local Git version control: git init and commit your initial working tree.
  • Use VS Code's split-screen feature to compare your database schema with your active PHP model file.
Expected Result: A clean, navigable workspace in VS Code with syntax highlighting and file-tree visibility.
Common Mistakes to Avoid: Opening individual files instead of the entire parent folder, breaking relative paths and IDE auto-completion.
Step 05

Debug Errors Using ChatGPT & Gemini Flash

Copy the Error, Investigate the Cause, Fix the Correct File, and Retest

Debugging is an engineering process. Do not guess fixes or rewrite entire applications when an error occurs. Locate the stack trace, isolate the offending file, and prompt the AI for targeted repairs.

5-Step Surgical Debugging Protocol:
  1. Capture the exact error message: Copy the full PHP Fatal Error, PDOException, or browser console stack trace.
  2. Inspect server error logs: Open C:\xampp\apache\logs\error.log or php_error_log.
  3. Sanitize before prompting: Strip sensitive database passwords, API tokens, and private client data.
  4. Prompt for root-cause diagnosis first: Ask ChatGPT: "Analyze this PHP PDO error. Explain the root cause before providing the fixed snippet."
  5. Apply targeted edits: Update only the affected function or file, save, and retest in your browser.
Expected Result: Rapid resolution of syntax, database, and logic errors without destabilizing working code.
Common Mistakes to Avoid: Pasting live API keys or production database credentials into public AI chat windows; modifying core files without backups.

Step 07

Deploy the Website to Hostinger

Move from Localhost to a Live Website

Transition your local XAMPP application to Hostinger's production cloud infrastructure, wire up a live MySQL database, configure SSL, and verify your live domain.

Hostinger Live Deployment Protocol:
  1. Log in to your Hostinger hPanel and verify your PHP version is set to 8.2 or 8.3.
  2. In phpMyAdmin (Local XAMPP), export your database: Quick → SQL format.
  3. In Hostinger hPanel, go to Databases → MySQL Databases. Create a database name and user with a strong password.
  4. Launch remote phpMyAdmin from hPanel and Import your exported SQL file.
  5. Compress your local project files into a .zip archive (exclude .git and local temporary logs).
  6. Use Hostinger File Manager or SFTP (FileZilla) to upload the zip to public_html.
  7. Extract the archive into public_html.
  8. Edit config/database.php with your live Hostinger database credentials.
  9. Ensure the SSL certificate is active and toggle Force HTTPS in hPanel.
  10. Verify that display_errors = Off in production to keep server path errors hidden.
  11. Perform a live smoke test: log in, run a test CRUD action, and submit the contact form.
Expected Result: A live, publicly accessible website protected by HTTPS, connected to an isolated cloud MySQL database.
Common Mistakes to Avoid: Leaving local credentials (localhost, root, empty password) in live configuration files; uploading unencrypted .env files to public directories.

Transactional Messaging

Send Website Emails with PHPMailer

Built-in PHP mail() often fails delivery checks because it lacks modern SMTP authentication, SPF/DKIM validation, and encryption headers. PHPMailer solves this reliably.

Common Email Workflows:

Public contact inquiries, user registration confirmations, password reset links, automated billing receipts, and immediate system error notifications.

Secure SMTP Configuration:

Always store your SMTP host, port, username, and password in environment variables outside the web document root — never hardcode credentials in public files.

src/Mailer.php — Clean Implementation 
<?php
use PHPMailer\PHPMailer\PHPMailer;
use PHPMailer\PHPMailer\Exception;

require 'vendor/autoload.php';

function sendTransactionalEmail($to, $subject, $htmlBody): bool {
    $mail = new PHPMailer(true);
    try {
        // SMTP Provider Configuration
        $mail->isSMTP();
        $mail->Host       = $_ENV['SMTP_HOST'];
        $mail->SMTPAuth   = true;
        $mail->Username   = $_ENV['SMTP_USER'];
        $mail->Password   = $_ENV['SMTP_PASS'];
        $mail->SMTPSecure = PHPMailer::ENCRYPTION_STARTTLS;
        $mail->Port       = 587;

        // Sender & Recipient Headers
        $mail->setFrom('no-reply@domain.com', 'Portal System');
        $mail->addAddress($to);

        // Payload
        $mail->isHTML(true);
        $mail->Subject = $subject;
        $mail->Body    = $htmlBody;

        return $mail->send();
    } catch (Exception $e) {
        error_log("Email Dispatch Failure: " . $mail->ErrorInfo);
        return false;
    }
}

* Note: Successful PHP code execution does not guarantee inbox delivery; verify that your domain's SPF, DKIM, and DMARC DNS records are correctly aligned.

Common Errors and Real-World Solutions

A practical reference for diagnosing and resolving real-world PHP, MySQL, Apache, and hosting errors.

Common Issue Underlying Root Cause Where to Investigate Recommended Solution
Apache does not start Port 80/443 conflict with Skype, IIS, or VMware. XAMPP Logs > Apache (error.log) Change port to 8080 in httpd.conf or stop conflicting background services.
MySQL does not start Corrupt transaction logs or another MySQL instance on 3306. xampp/mysql/data/mysql_error.log Kill existing MySQL background processes or rename corrupt aria_log files.
Localhost returns 404 Incorrect subfolder name or missing index.php. C:\xampp\htdocs\[folder_name] Verify project files reside directly inside htdocs with correct spelling.
PHP Parse / Syntax Error Missing semicolon, unclosed brace, or outdated PHP version. Browser screen & VS Code Problems tab Check line numbers in the stack trace and verify opening/closing braces.
DB Connection Failure Wrong port, invalid password, or stopped MySQL service. config/database.php Verify credentials in phpMyAdmin; check username, password, host, and port.
Unknown Database Error Database has not been created or the name has a typo. phpMyAdmin > Databases list Run CREATE DATABASE db_name and ensure the name matches database.php.
Unknown Table or Column Schema migration was not executed or column name is misspelled. database/schema.sql vs MySQL Table Re-import schema.sql and ensure your query column names match definitions.
Login Session Failure session_start() missing, called too late, or cookie blocked. auth/login.php & header.php Ensure session_start() is the first statement before any HTML output.
CRUD Does Not Update Missing WHERE condition, CSRF mismatch, or unfetched form fields. admin/controllers/update.php Inspect $_POST using var_dump(); verify the primary key ID exists in query.
Missing CSS / JS Assets Incorrect absolute paths or broken relative links. Browser DevTools > Network tab Use base root paths like /assets/css/style.css instead of ../../.
PHPMailer Auth Failure Invalid SMTP credentials, blocked port 587, or missing app password. SMTP Debug ($mail->SMTPDebug = 2) Generate an App-Specific Password (for Gmail) and verify TLS port configuration.
HTTP 500 on Live Hosting Incompatible PHP version, syntax error, or bad .htaccess. Hostinger hPanel > Error Logs Inspect the server error log in hPanel; verify live PHP version matches local setup.
Upload Permission Denied Web server user does not have write permissions on uploads folder. uploads/ directory permissions Set upload directory permissions to 755 (chmod -R 755 uploads/) on server.
